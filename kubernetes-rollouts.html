What to check when a Kubernetes rollout stalls

A stalled Deployment is a symptom. Start by finding out whether Kubernetes can schedule the new Pods, pull the image, start the container, and mark it ready.

1. Confirm what you’re inspecting

Verify the cluster context and namespace first. Check whether the Deployment has the new image and how many updated replicas are available. The example below uses a Deployment called api in namespace qa. Replace those names with the ones you intend to inspect.

kubectl config current-context
kubectl -n qa rollout status deployment/api --timeout=60s
kubectl -n qa describe deployment api
kubectl -n qa get pods -o wide

The client timeout bounds how long the first status command waits. A Deployment condition of ProgressDeadlineExceeded is a separate signal from the controller that the rollout has stopped progressing within its configured deadline.

2. Find the Pod that explains the failure

Look at the new ReplicaSet and its Pods. Use kubectl describe pod for events. If the container starts and exits, inspect its logs and use --previous for the last terminated instance, when available.

  • Pending: Look for scheduling events, insufficient resources, or constraints that prevent placement.
  • ImagePullBackOff: Check the exact image reference, registry access, and pull credentials.
  • CrashLoopBackOff: Read the container’s logs and check its exit reason, required configuration, and dependencies.
  • Running but unready: Check readiness probe settings, the listening port, and whether the application is ready to accept traffic.

3. Pick a recovery path and verify it

If the release is affecting users, follow the environment’s approved rollback process. Where Helm or a GitOps controller owns the Deployment, use the release tool or reconcile the source of truth so it does not reapply the failed change. After recovery, confirm available replicas and smoke test the application. Deployment status checks Kubernetes state. The smoke test checks what users can reach.

Reference: Kubernetes documentation on Deployments and rollout status.
